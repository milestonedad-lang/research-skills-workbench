## 已覆盖的重要行为

- 2月平年/闰年、30天月份、上海时区跨日月末判断。
- 部分来源失败保留旧数据；快照失败/错误hash不替换原目录；失败尝试记录与启动限频。
- 目录与安装分离，缓存不被误报为当前安装；未知正文不误作重复技能。
- 上游删除保留安装历史；安装失败不切换；不同技能替代能回退原技能；本地包修改后拒绝按原版本执行。
- 二进制资源安装与导出按原始字节保持一致。
- 输入不可覆盖；任务启动保存资料、模型及技能版本；比较批次创建时固定模型配置。
- 取消比较后剩余试验记为未运行；无法预留下一次请求费用时停止整个比较。
- 失败和未评分不能因速度快而优胜；数值结果需成功执行证据；引用需真实工具元数据一致；图表有匿名PNG预览。
- 默认无推荐；不跨固定配置的批次合并排名。

## 尚未实际验证或发布

1. **真实生成模型效果**：本机没有用户配置的API密钥或可用Ollama模型，未调用付费模型、未产生真实技能胜负排名。需在设置中配置模型，再使用公开样例与预算完成实测。
2. **Docker执行**：本机未安装Docker，未真实运行隔离代码容器、超时/取消容器与科研绘图。提供 `scripts/runner_smoke.py`，CI runner job会构建镜像并实际计算、生成PNG、检查输入只读；CI运行结果仍待远程发布后查看。
3. **新电脑与其他系统**：当前Windows环境启动通过，干净新电脑、Linux/macOS与Compose仍需实机验证；CI包含Windows/Linux后端，运行成功前不主张已验收。
4. **GitHub部署**：当前为本地开发分支 `feature/workbench-v0.1`。远程分支/PR与定时工作流是否生效，须在指定仓库上传并查看Actions结果。仅推送开发分支不会启用默认分支定时扫描。
5. **科研有效性**：首版基准为公开小样例，只能验证相应任务约束；不能替代领域专家检查、实验复现或大规模真实任务评测。

## 用户环境验收步骤

1. 按 [部署指南](DEPLOYMENT.md) 启动，断开网络后检索中文用途与英文名称。
2. 配置自己的模型，先运行写作任务，下载报告与查看执行记录。
3. 构建runner并运行smoke检查，随后用sample.csv执行分析/绘图。
4. 在比较中心选两个相关技能，以固定条件、预算及三次重复测试，完成匿名评分。
5. 在详情确认替代，核对后续任务版本；更新中心回退并核对历史。
6. 合并工作流到默认分支后手动扫描；启动平台同步并检查安装版本保持固定。
7. 提交或分享前核查Git忽略列表，确保data、密钥、私人资料及本地测试目录不在仓库。
